# CricketCanClubs phone app (Expo / React Native)

One app for **iPhone and Android** (decision Oct 28 2026: Expo instead of separate Swift + Kotlin apps, so the
iPhone app can be built in Expo's cloud from Windows - no Mac needed). It shows the CricketCanClubs website with
native extras: bottom tabs (Home, Live, Score, Scorecards, Upload), camera / photo library for scorecard photos,
pull down to refresh (iPhone; on Android tap the open tab again), Android back button, "No internet" screen,
WhatsApp / phone / email links open in their own apps, app icon and splash screen.

- Code: `App.tsx` (screen, tabs, web view), `src/config.ts` (website address and tabs), `app.json` (name, icon,
  permissions, ids `com.cricketclubapp`), `eas.json` (cloud builds).
- Website address: `src/config.ts` -> `BASE_URL` (or `EXPO_PUBLIC_BASE_URL=... npx expo start`).
- Expo SDK 58. Always add packages with `npx expo install <name>` (picks versions that match the SDK).
- `ios/` and `android/` are generated by Expo when building - never edit or commit them.

## Try it on your phone (Windows, 10 minutes)
1. Install **Node.js LTS** from nodejs.org (Next on every screen).
2. On the phone install **Expo Go** from the Play Store / App Store.
3. In a terminal: `cd C:\Users\dhruv\Desktop\CricketCanClubsFresh\mobile` then `npm install` then `npx expo start`.
4. A QR code appears. Android: open Expo Go and scan it. iPhone: scan it with the Camera app.
   Phone and laptop must be on the same Wi-Fi (or run `npx expo start --tunnel`).

## Build real app files in Expo's cloud (no Android Studio, no Mac)
1. Create a free account at expo.dev. In the `mobile` folder: `npx eas-cli@latest login`, then `npx eas-cli@latest init`
   (links the project; writes its id into app.json - commit that change).
2. Android test file to install on phones: `npm run build:android-test` -> a download link for an .apk.
3. Store builds: `npm run build:android` (.aab for Google Play) and `npm run build:ios` (asks for the Apple
   Developer login - Amit's - and makes the certificates itself).
4. Send to the stores: `npm run submit:ios` (App Store Connect / TestFlight) and `npm run submit:android`
   (needs a Google Play service-account key, or upload the .aab by hand in Play Console the first time).
5. Each new store version: raise `version` (and `ios.buildNumber`, `android.versionCode`) in app.json.

Store steps, dates and the Google Play 12-testers / 14-days rule: `MD/PHONE_APPS.md`.
